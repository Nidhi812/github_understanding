for configure git at global level 
-> git config --global user.name "Your name"
-> git config --global user.email "your.email@example.com"

or at the local level yopu just have to remove the --global from the command and it set your name and email to that particular repository in which you're working 

->git config user.name "Your name"
-> git config user.email "your.email@example.com"

to check the configuration settings applied just to the repository 
-> git config --local --list 

then initialize your project repository 
-> git init 

for creating or modify your files 
-> touch your_filename 

for checking the status 
-> git status (it tells about the untracked and tracked file)

to move the files from the modified area to the staging area 
-> git add your_filename      (this si used to a particular file to the repository)
        OR
-> git add .    (this is used to add all files in the repository)
and after that we can check the status of the repository file 

for commiting the staged changes to the local repository history 
-> git commit -m "A meaningful message to be written here"

after commit we can check the or view the history by 
-> git log 

for connecting on github some few steps are as follows:-
1-> create a new or empty repository on github 

2-> then link your local repository to the remote on the github 
-> git remote add origin <url> 

3-> Pushes your local comit to the main branch 
-> git push -u origin main (or master)

if it is not working then craete a branch 
-> git branch (here we can chcek the branch as what are the branches are available in our repository)

or create by like 
-> git branch main (main main is created by default in our repo) [then repeate the 3 step ]

4-> Pull and integrates changes to the remote repo to the local repo or get the updates
-> git pull origin main

Branching and Merging (Collaboration)

it allows multiple people(or features) work in parallel

1-> create a branch 
-> git branch new-feature

2-> Switch to the branch 
-> git checkout new-feature

3->In one step to create a branch and immediately switch to that particula branch 
-> git checkout -b bug-fix

4-> if you want to work on that particular branch and commit and same steps have to be follow to work on it 

5-> Switch back to the previous or some other branch 
-> git checkout main 

5-> Merge changes 
-> git merge new-feature   [it integrates the commit changes from new-feature to the current main feature 

====================================================================================================

Standard github workflow (Pull Request)

when working with others, we rarely merge directly. Instead of directly merger we do pull request 

1-> Craete a new branch  (e.g., git checkout -b feature/login-page).

2-> Commit your work (on the branch).

3-> Push your branch on github (git push origin feature/login-page).

4-> Create a pull request(pr) on the github website
    -> this is a request to merge your branch into the main 
    -> it allows code review and discussion before merge

5-> review and merge on github website(someone else approves it and merge it)

6-> Clean up locally(git branch -d feature/login-page) it will delete the local branch after the merge
